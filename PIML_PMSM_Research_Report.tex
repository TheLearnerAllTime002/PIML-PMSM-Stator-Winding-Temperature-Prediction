\begin{abstract}
This paper reports an exploratory study of permanent-magnet temperature
prediction in a permanent-magnet synchronous motor (PMSM). The data contain
1,330,816 measurements from 69 operating profiles. The project combines
physics-derived features with recurrent thermal state-space models and now
includes a modular ablation runner, profile-level statistical analysis, and
five-fold profile-grouped comparisons. In a reduced-budget evaluation, Ridge
direct forecasting achieved pooled 20-step MAE $=0.0944\,^{\circ}$C, compared
with $0.1051\,^{\circ}$C for a direct GRU, $0.1056\,^{\circ}$C for a direct
LSTM, $0.1095\,^{\circ}$C for the operating-conditioned thermal model, and
$0.1227\,^{\circ}$C for persistence. These are preliminary screening results:
training used 1\% of available windows for three epochs, and hyperparameter
selection was not nested within outer cross-validation. Profile-level paired
tests favored Ridge and the direct recurrent models, while corrected fold-level
tests did not remain significant after multiplicity correction. The results
therefore do not establish model superiority. The target and input assumptions
must also be stated precisely: the target is permanent-magnet temperature, and
the 20-step comparison uses recorded future ambient temperature.
\end{abstract}

\begin{IEEEkeywords}
PMSM, thermal prediction, physics-informed machine learning, LSTM,

\section{Introduction}
PMSMs are used in electric vehicles, industrial drives, robotics, and other
high power-density applications. Their operating envelope is constrained by
thermal behavior: excessive winding or magnet temperature accelerates
insulation ageing, changes electrical parameters, and may cause protection
events or permanent damage. A temperature estimator can support derating,
fault prevention, and condition monitoring.

The project develops a hybrid predictor instead of relying only on a black-box
regressor. Electrical measurements are transformed into current magnitude,
voltage magnitude, electrical power, mechanical power, and a copper-loss
proxy. Recurrent models then represent thermal memory and learn a bounded
thermal response. The notebook also evaluates unseen operating profiles,
multi-step forecasts, stability, residual magnitude, and SHAP importance.

The central result is two-sided. The models achieve very strong one-step and
20-step errors on the available data, but the experiments themselves reveal
that a model can appear accurate while failing to reproduce slow temperature
drift. This paper therefore reports both the successful results and the
evidence that must be addressed before journal submission.

\section{Research Progress and Project Goals}
I proceeded through the project in stages. I first established a reproducible
baseline using the available PMSM measurements. I then added physically
motivated features, separated the operating profiles into train, validation,
and test groups, and evaluated classical and neural regressors. After this
initial comparison, I developed recurrent thermal state-space models to
represent thermal memory and multi-step temperature evolution. Finally, I
trained an energy-constrained residual model, generated SHAP explanations, and
connected the saved model to a Streamlit realtime demonstration.

The original goals were: (i) predict motor temperature accurately, (ii) use
physics to improve generalization, (iii) test the model on unseen operating
profiles, (iv) explain the model decisions, (v) estimate thermal risk/RUL, and
(vi) provide a usable demonstration. Goals (i)--(iv) have been substantially
achieved. Goal (v) has only been achieved as a thermal-limit proxy because the
dataset contains no run-to-failure labels. Goal (vi) has been achieved as a
local website, but its reliable deployment requires a rolling sensor history
rather than slider values alone.

\section{Data and Preprocessing}
The source file is the electric-motor measurement dataset used by the notebook.
It contains 1,330,816 rows, 69 profile identifiers, electrical variables,
mechanical variables, coolant and ambient temperatures, and four temperature
channels. The current recurrent pipeline predicts the permanent-magnet
temperature, denoted by $T_{pm}$, not the column named
\texttt{stator\_winding}. This distinction must be corrected in the title,
figures, and claims if the paper is intended to predict winding temperature.

The notebook splits by profile rather than randomly by row. The reported split
contains 48 training profiles, 10 validation profiles, and 11 test profiles.
The input order stored in the saved scaler and checkpoints is
\begin{equation}
 [u_q,\;coolant,\;u_d,\;speed,\;i_d,\;i_q,\;\tau,\;ambient,
 I_{mag},V_{mag},P_{elec},P_{mech},P_{cu}].
\end{equation}
Numerical features are standardized using a scaler fitted on the training
profiles only. Each recurrent input is a sequence of 128 samples.

The engineered quantities are
\begin{align}
 I_{mag} &= \sqrt{i_d^2+i_q^2},\\
 V_{mag} &= \sqrt{u_d^2+u_q^2},\\
 P_{elec} &= u_di_d+u_qi_q,\\
 \omega &= 2\pi\,speed/60,\\
 P_{mech} &= \tau\omega,\\
 P_{cu} &= 0.05I_{mag}^2.
\end{align}
The coefficient $0.05$ is an assumed resistance proxy rather than a measured
temperature-dependent winding resistance; this is a limitation of the
physics interpretation.

\section{Models}
\subsection{State-Space Thermal Models}
The notebook first trains fixed, adaptive, stable, and operating-condition
thermal state-space models. Their update equations have the general form
\begin{equation}
 T_{k+1}=T_k+\alpha\left(H_k-\beta(T_k-T_{a,k})\right),
\end{equation}
where $H_k$ is a learned heating signal, $T_a$ is ambient temperature, and
$\alpha$ and $\beta$ are learned bounded coefficients. The adaptive model
uses a two-layer LSTM encoder and predicts thermal parameters from its latent
state.

\subsection{Energy-Constrained Residual Model}
The RQ4 model combines a recurrent thermal prediction with an energy-residual
correction. The correction is bounded to prevent numerical explosion. The
training objective includes temperature error, trajectory-difference error,
smoothness regularization, and residual regularization. The saved
\texttt{rq4\_v2\_best.pth} checkpoint is an LSTM-based 20-step model. Its
reported validation result is not better than the adaptive baseline, despite
the additional residual pathway.

\section{Evaluation Metrics}
The study uses mean absolute error, root mean squared error, and coefficient of
determination:
\begin{align}
 MAE &= N^{-1}\sum_i|y_i-\hat y_i|,\\
 RMSE &= \sqrt{N^{-1}\sum_i(y_i-\hat y_i)^2},\\
 R^2 &= 1-\frac{\sum_i(y_i-\hat y_i)^2}{\sum_i(y_i-\bar y)^2}.
\end{align}
Metrics are reported in degrees Celsius for temperature prediction.

The overall Friedman test was significant ($\chi^2=118.35$, $p=1.20\times
10^{-24}$). Paired profile-level Wilcoxon tests with Holm correction favored
Ridge, direct GRU, and direct LSTM over the thermal reference. Nadeau--Bengio
corrected fold tests did not remain significant after Holm correction. Given
the limited training fraction and non-nested hyperparameter screen, these
comparisons are hypotheses for a confirmatory run, not final evidence of
superiority.

For the 20-step RQ4 forecast, horizon-wise MAE increases from approximately
0.0380 $^{\circ}$C at step 1 to 0.1344 $^{\circ}$C at step 20. This monotonic
increase is expected in recursive thermal forecasting and should be shown in
the paper rather than only the aggregate $R^2$.

\section{What Has Been Achieved}
The project has achieved the following research components:
\begin{enumerate}[leftmargin=1.5em]
\item a profile-disjoint preprocessing and evaluation protocol;
\item physics-derived electrical and mechanical features;
\item trained and saved LSTM/state-space checkpoints;
\item multi-step prediction up to 20 steps;
\item unseen-profile and persistence-baseline evaluation;
\item a working local Streamlit demonstration;
\item saved-model SHAP global importance analysis;
\item a modular 32-variant ablation and baseline evaluation runner;
\item profile-cluster bootstrap, Wilcoxon-Holm/BH, Friedman-Nemenyi,
Diebold--Mariano with capped HAC bandwidth, and Nadeau--Bengio analyses.
\end{enumerate}
The SHAP analysis ranks $P_{cu}$, motor speed, voltage magnitude, axis currents,
and torque as important model inputs. This is physically plausible because
current magnitude drives the assumed copper-loss term and speed/torque describe
mechanical loading. SHAP importance indicates model sensitivity, not causal
heat percentages.

\section{Evidence That Prediction Is Still Wrong}
The notebook contains direct evidence that long-term prediction is not yet
reliable. On hard unseen profile 21, the observed temperature increases from
approximately 27.6 $^{\circ}$C to 49.3 $^{\circ}$C over 500 samples while the
stable thermal equation predicts only 29.6 $^{\circ}$C. The model trajectory is
smooth, but it is too flat. In the same diagnostic, predicted absolute
step-to-step change has maximum 0.062 $^{\circ}$C, whereas the measured maximum
is 3.63 $^{\circ}$C. A smooth trajectory is therefore not sufficient evidence
of physical correctness.

The underlying reason is visible in the experiment: the model is asked to
roll out future temperature while future operating inputs are held constant.
In profile 21, the real copper loss changes slightly, but the accumulated
thermal trajectory is not captured by a constant forcing term. In addition,
the bounded $\tanh$ cooling law can saturate, preventing cooling from
increasing proportionally with the temperature difference. Finally, the
realtime website currently repeats a single snapshot 128 times. This differs
from training, where each window contains a real sequence of 128 measurements.
The resulting prediction can be an out-of-distribution response even when the
slider values are numerically plausible.

\section{Recommended Correction}
Changing the model should not be the first intervention. The input interface
must first match the training contract:
\begin{enumerate}[leftmargin=1.5em]
\item maintain a rolling buffer of the latest 128 synchronized sensor rows;
\item compute the five engineered features using the same formulas and scaler;
\item use the measured latest $T_{pm}$ as the initial state;
\item pass future ambient and operating inputs when forecasting offline;
\item for live deployment, explicitly state the future-input assumption;
\item validate the website output against notebook predictions on identical
windows before interpreting the dashboard.
\end{enumerate}

For a practical realtime system, the input method should be changed from
independent sliders to a CSV/live-stream buffer. Sliders are useful for a
demonstration, but they cannot recreate thermal memory. The correct website
design is a manual override mode plus a streaming mode that accepts 128 rows.

\section{Should a Different Model Be Used?}
Yes, but only after the input mismatch is corrected. The preferred next model
is a direct multi-horizon LSTM or GRU that predicts the full 20-step trajectory
from a 128-step history and receives a planned future operating sequence. A
hybrid update may be written as
\begin{equation}
 T_{k+1}=T_k+\Delta T_{physics}(T_k,T_{a,k},P_{cu,k})
             +r_k,
\end{equation}
where $r_k$ is learned and bounded. Unlike the present constant-forcing
rollout, $P_{cu,k}$ and other known future inputs vary with $k$.

The model-selection experiment should compare persistence, the existing
adaptive LSTM, a direct multi-horizon LSTM/GRU, and the hybrid model under the
same profile-disjoint splits. Selection should be based on 20-step and
500-step trajectory MAE, not only one-step MAE or $R^2$. The current notebook
already shows that the RQ4 residual model does not improve over the adaptive
baseline on its reported 20-step validation result, so it should not currently
be presented as the best model.

\section{RUL and Deployment Claims}
The available dataset contains no run-to-failure records, degradation labels,
or validated failure threshold. Therefore, the current thermal-limit RUL
output is a proxy defined as forecast steps until $T_{pm}$ reaches a configured
limit. It is useful for a demonstration, but it is not empirical component-life
RUL. A journal paper should either obtain ageing/run-to-failure data or rename
the output to ``thermal-limit horizon'' and report its censoring rate.

\section{Limitations and Reproducibility}
The assumed copper resistance, simplified lumped thermal equation, constant
future forcing in long rollouts, and target distinction between $T_{pm}$ and
stator-winding temperature limit external validity. The source data are sampled
at 2 Hz, so forecast steps correspond to 0.5 seconds each. The saved scaler was
generated with a different scikit-learn version than the current environment,
so the production environment should pin library versions and archive the exact
preprocessing code.

The realtime application is launched with:
\begin{verbatim}
streamlit run PMSM_EDSS/app.py
\end{verbatim}
The saved-model SHAP/RUL analysis is launched with:
\begin{verbatim}
python Explainability/shap_rul_analysis.py
\end{verbatim}

\section{Conclusion}
Through this work, I progressed beyond a preliminary regression experiment: I
implemented profile-disjoint evaluation, recurrent physics-informed models,
saved checkpoints, multi-step metrics, unseen-profile testing, explainability,
a local demonstration, and a modular ablation/statistical evaluation pipeline.
The current reduced-budget comparison identifies Ridge and direct recurrent
models as important competitors to the adaptive thermal model, but the evidence
does not establish robust superiority for any method. The study does not yet
support validated long-term thermal digital-twin or component-RUL claims.

The main challenges were the limited physical labels, distinction between
magnet and winding temperatures, long-horizon drift, and the initial website
input that did not preserve thermal history. I addressed these challenges
through profile-wise testing, physics-derived variables, bounded recurrent
models, explicit ablation and baseline experiments, profile-level statistical
tests, SHAP analysis, and a corrected CSV-history input mode in Streamlit. The
next step is a nested grouped evaluation with a full training budget and a
pre-specified forecast-input protocol.

The next research milestone is clear: make the website consume a real rolling

multi-horizon model with time-varying future operating inputs. Only after that
comparison should a new architecture be selected for publication.
